## Description

ESP-IDF constraint files now include a large autogenerated **UPPER BOUNDS** block. Most of those lines carry a `python_version` marker.

The wheel pipeline used to treat every line from the downloaded constraint files like an ordinary requirement. Those caps were merged into the build list alongside real ESP-IDF requirements. That had two effects:

1. Caps that are not pulled in by any requirement were still queued as packages to build.
2. Hundreds of marker-bearing lines were copied into **python-version-dependent** rebuild lists, so other Python jobs tried to compile the whole set from source, bypassing the normal exclude/include behaviour and failing (for example Pillow on Linux, timeouts on ARMv7).

**This PR does not delete the upper-bounds block from the downloaded constraint file.** The block stays in the constraint text and is passed to `pip` with `-c` during a per-release **dry-run solve**. What changes is how those files are used afterward:

- Each ESP-IDF branch (release or master) is resolved on its own: branch requirements + that branch’s constraint file (upper bounds included).
- Platform/Python exclusions are applied to the resolver inputs first, so unsupported packages such as ARMv7/Python 3.8 `cryptography` cannot fail resolution before being excluded.
- `pip install --dry-run --report` produces an exact `name==version` pin set for that release.
- The union of pins across releases is what gets built. Wheels are built with `pip wheel --no-deps`, so versions are not resolved a second time.
- Constraint-only lines are not added to `requirements.txt` or the sdist listing as packages to build. Pip options such as `--only-binary …` are collected separately and still applied at wheel time.
- Esptool dependencies are solved once in their own group, not re-resolved against every release’s constraint file.
- The exclude list is applied so exact pins are **kept or dropped**, not rewritten into open ranges (which would break `--no-deps` builds).
- Other Python versions rebuild only **`cp*`-tagged wheels** from the current pin set; stale wheels in `downloaded_wheels/` and pure `py3-none-any` pins are not blindly copied.
- Pinned wheels are built before the include list so find-links can satisfy overlapping dependencies.
- Missing constraint files abort **release** branches; **master** (including a transient missing constraints file) can resolve without constraints instead of killing the whole job.

## What stays the same

- One platform job still builds the wheels; there is no new job per ESP-IDF branch.
- The same exclude list, include list, and per-package wheel policies (find-links, ARMv7, macOS Intel cryptography, etc.) apply.
- Exclusions are also checked after resolution as a safety net, while the original requirement lines remain available for sdist calculation.
- Packages that appear only as a version cap in the constraint file and are not selected by the solve are still not built.
